# Install with the SAME python3/pip you use to run scripts/train.py and
# scripts/run_sweep.py -- if you have more than one Python installed
# (Homebrew, pyenv, system /usr/bin/python3, etc.), a package installed
# for one of them will not be visible to another, which is exactly what
# causes a "ModuleNotFoundError" even though the package appears to be
# installed. To be sure, use:
#
#   python3 -m pip install --upgrade -r requirements.txt
#
# numpy and torch are pinned to an exact, tested-together pair (rather
# than a loose lower bound) because a PyTorch build compiled against
# NumPy 1.x will crash with confusing numpy-related errors if a newer
# NumPy 2.x gets installed next to it without upgrading PyTorch too --
# pinning both forces pip to bring them into a matched pair instead of
# silently leaving a stale, incompatible one in place. --upgrade above
# is what makes pip actually replace an existing mismatched install
# rather than treating "torch is already present" as satisfied.
